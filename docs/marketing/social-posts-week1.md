## Reddit

### r/cscareerquestions — System design tips (Tue)
**Title:** A 4-phase framework that stopped me from freezing in system design interviews

**Body:**
```
System design used to be my worst round. I'd hear "design Twitter" and my brain would go blank.

Here's the framework that helped:

**Phase 1 (3-5 min): Requirements** — Ask about scale, read vs write ratio, latency SLAs. Don't draw anything yet.

**Phase 2 (10-12 min): High-level design** — Clients → LB → app servers → DB/cache/queue. One primary user flow end-to-end.

**Phase 3 (15-18 min): Deep dives** — Interviewer picks 1-2 areas. Be specific: "I'd use Redis here because we need sub-ms reads and can tolerate eventual consistency."

**Phase 4 (5-7 min): Scale & monitor** — What breaks at 10x? What alerts do you set up?

The biggest mistake is skipping Phase 1. If you're discussing sharding before you know the read/write pattern, you're in trouble.

I've been practicing with timed mocks and an AI tool that suggests component diagrams when I get stuck (Kraken Interview — full disclosure, I'm affiliated). Happy to answer questions about specific system types.
```

### r/leetcode — Prep beyond grinding (Fri)
**Title:** Solved 300+ LeetCode problems and still failed interviews — what actually helped

**Body:**
```
Not trying to discourage grinding — patterns matter. But after 300+ problems I still bombed a Google loop because:

1. I couldn't explain my thought process out loud
2. System design was a separate skill I never practiced
3. Behavioral answers were unstructured rambling

What moved the needle:
- Mock interviews with humans (Pramp, friends)
- Building small projects (rate limiter, KV store) instead of more random mediums
- Practicing STAR stories out loud, timed to 2 minutes
- Full-loop simulations with time pressure

For solo practice I use Kraken Interview (disclosure: I'm the maker) — it simulates the overlay + voice context thing. Not a replacement for mocks with humans, but good for 11pm practice sessions.
```
